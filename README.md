# ระบบเช็คชื่อเข้าร่วมกิจกรรมด้วยใบหน้า (Face Attendance System)

ระบบเช็คชื่อนักเรียนด้วยการจดจำใบหน้า ออกแบบสำหรับฐานข้อมูลนักเรียนระดับ ~2,000 คน
รันบน Windows ด้วย Python, เก็บข้อมูลใน SQLite (ไฟล์เดียว ไม่ต้องติดตั้ง server ฐานข้อมูลแยก)

## โครงสร้างไฟล์

```
face_attendance_system/
├── main.py            # โปรแกรมหลัก (GUI) - รันไฟล์นี้เพื่อเปิดโปรแกรม
├── config.py           # ค่าตั้งค่าต่างๆ (เกณฑ์ความแม่นยำ, ขนาดกล้อง ฯลฯ)
├── database.py         # เลเยอร์ฐานข้อมูล SQLite
├── face_engine.py       # ตรวจจับ + จดจำใบหน้า (InsightFace)
├── camera_utils.py      # เปิดกล้องแบบ background thread
├── export_utils.py      # ส่งออกรายงานเป็น Excel
├── requirements.txt
└── data/                # สร้างอัตโนมัติ: attendance.db, exports/, student_photos/
```

## การติดตั้งบน Windows

1. ติดตั้ง **Python 3.10 หรือ 3.11** (แนะนำ ไม่ใช่ 3.12/3.13 เพราะบางไลบรารี AI ยังรองรับไม่เต็มที่)
   ดาวน์โหลดจาก https://www.python.org/downloads/ (ตอนติดตั้งให้ติ๊ก "Add Python to PATH")

2. เปิด Command Prompt ในโฟลเดอร์โปรเจกต์ แล้วสร้าง virtual environment:
   ```
   python -m venv venv
   venv\Scripts\activate
   ```

3. ติดตั้งไลบรารีทั้งหมด:
   ```
   pip install -r requirements.txt
   ```

   > **หมายเหตุ:** ถ้า `pip install insightface` ขึ้น error เกี่ยวกับการคอมไพล์ (ต้องการ Visual C++ Build
   > Tools) ให้ติดตั้ง "Microsoft C++ Build Tools" จาก
   > https://visualstudio.microsoft.com/visual-cpp-build-tools/ ก่อน แล้วรันคำสั่ง pip install ใหม่
   > (ปกติ insightface มี wheel สำเร็จรูปสำหรับ Windows อยู่แล้ว ส่วนใหญ่ไม่ต้องคอมไพล์)

4. รันโปรแกรม:
   ```
   python main.py
   ```

   ครั้งแรกที่รัน โปรแกรมจะดาวน์โหลดโมเดล InsightFace (~300 MB) อัตโนมัติ ต้องต่ออินเทอร์เน็ตครั้งแรกเท่านั้น
   ครั้งถัดไปจะโหลดจากเครื่อง (`C:\Users\<ชื่อผู้ใช้>\.insightface\`)

## การจัดการข้อมูลสาขา

ระบบเก็บข้อมูล **"สาขา"** ของนักเรียนแยกจากห้อง/กลุ่มเรียน:
- **นำเข้าอัตโนมัติ:** ถ้านำเข้าจากไฟล์รายงาน สอศ. ระบบจะดึงค่า "ชื่อกลุ่มเรียน" มาใส่เป็นสาขาให้อัตโนมัติ
- **นำเข้าด้วยเทมเพลต:** เทมเพลตมีคอลัมน์ "สาขา" ให้กรอกเองได้ (หรือใช้หัวคอลัมน์ "แผนก"/"department" ก็ได้)
- **กรอกด้วยมือ:** มีช่อง "สาขา:" ในฟอร์มเพิ่มนักเรียนทีละคน
- **กรองข้อมูล:** แท็บ "จัดการนักเรียน" มี dropdown "สาขา:" กรองรายชื่อแยกจากตัวกรองห้อง
- **รายงาน:** กราฟสรุปในแท็บ "รายงาน" มี 3 ส่วน (ภาพรวม / แยกตามห้อง / **แยกตามสาขา**)
  และไฟล์ Excel ที่ export มีคอลัมน์สาขา + ตารางสรุปแยกตามสาขาในชีท "สรุปภาพรวม"

## เงื่อนไขการนับ "เข้าร่วมกิจกรรม" (สแกนเข้า + สแกนออก)

ระบบนับว่า **"เข้าร่วมกิจกรรม"** เฉพาะนักเรียนที่มีการสแกนใบหน้าทั้ง **"เข้า"** และ **"ออก"** เท่านั้น
ถ้าสแกนแค่ฝั่งเดียว (เข้าอย่างเดียว หรือ ออกอย่างเดียว) หรือไม่สแกนเลย จะถูกนับเป็น
**"ไม่เข้าร่วมกิจกรรม"** ในรายงานทุกกรณี

**วิธีใช้งาน:** ในแท็บ "เช็คชื่อ" มี dropdown **"โหมดสแกน:"** ให้เลือก
- ตอนเปิดงาน/ต้นกิจกรรม: ตั้งเป็น **"สแกนเข้า"** แล้วเปิดกล้องให้นักเรียนสแกนตอนเข้างาน
- ตอนปิดงาน/ท้ายกิจกรรม: กดหยุดกล้อง เปลี่ยน dropdown เป็น **"สแกนออก"** แล้วเปิดกล้องอีกรอบให้สแกนตอนออกจากงาน
- ต้องหยุดกล้องก่อนจึงจะเปลี่ยนโหมดได้ (กันสลับโหมดพลาดระหว่างทำงาน)

## กราฟสรุปผลการเข้าร่วม

แท็บ "รายงาน" มีแท็บย่อย **"สรุปภาพรวม"** แสดงกราฟ:
- กราฟวงกลมโดนัท: สัดส่วนเข้าร่วม/ไม่เข้าร่วมกิจกรรม
- กราฟแท่ง: จำนวนแยกตามห้อง/กลุ่มเรียน

กราฟนี้จะถูกฝังลงในไฟล์ Excel ที่ export ด้วยอัตโนมัติ (ชีท "สรุปภาพรวม")

## การสำรอง/กู้คืนข้อมูล

ข้อมูลทั้งหมด (นักเรียน, ใบหน้าที่ลงทะเบียน, กิจกรรม, ประวัติเช็คชื่อ) อยู่ในไฟล์เดียวคือ
`data\attendance.db` — แนะนำสำรองข้อมูลเป็นประจำ โดยเฉพาะก่อนนำเข้ารายชื่อจำนวนมากหรือก่อน
อัปเดตระบบเวอร์ชันใหม่

**วิธีสำรอง:** เมนู **"ไฟล์" > "สำรองข้อมูล (Backup)..."** เลือกตำแหน่งที่จะบันทึก
(แนะนำเก็บใน USB หรือ Google Drive แยกจากเครื่องนี้ เพราะข้อมูลใบหน้าเป็นข้อมูลอ่อนไหวตาม PDPA
ควรเก็บสำเนาสำรองไว้อย่างปลอดภัยเช่นกัน)

**วิธีกู้คืน:** เมนู **"ไฟล์" > "กู้คืนข้อมูลจากไฟล์สำรอง (Restore)..."** เลือกไฟล์ .db ที่เคยสำรองไว้
⚠️ การกู้คืนจะแทนที่ข้อมูลปัจจุบันทั้งหมด ควรสำรองข้อมูลปัจจุบันไว้ก่อนถ้ายังไม่แน่ใจ

## การเลือกกล้อง

ถ้าเครื่องมีกล้องหลายตัว (เช่น กล้องในตัวโน้ตบุ๊ก + เว็บแคมเสียบเพิ่ม) จะมี dropdown "กล้อง:"
ให้เลือกทั้งในแท็บ "จัดการนักเรียน" (ตอนลงทะเบียนใบหน้า) และแท็บ "เช็คชื่อ"
- กด "รีเฟรชรายการกล้อง" ถ้าเพิ่งเสียบกล้องใหม่หรือรายการยังไม่อัปเดต
- ระบบจะจำกล้องที่เลือกไว้ล่าสุดไว้ให้ (บันทึกในฐานข้อมูล) ไม่ต้องเลือกซ้ำทุกครั้งที่เปิดโปรแกรม

## วิธีใช้งาน

### ขั้นตอนที่ 1: ลงทะเบียนนักเรียน (Tab "จัดการนักเรียน")

**วิธี A - นำเข้าทีเดียวหลายคน (แนะนำสำหรับ 2000 คน):**
1. กด "ดาวน์โหลดเทมเพลต" จะได้ไฟล์ Excel ตัวอย่าง (คอลัมน์ รหัสนักเรียน / ชื่อ-สกุล / ห้อง)
   **หรือใช้ไฟล์รายงานรายชื่อที่ export จากระบบทะเบียน สอศ. ได้เลยโดยไม่ต้องแก้ไขไฟล์**
   (ระบบรู้จักฟอร์แมตที่มีแถวหัวเรื่อง/ชั้นปีแทรกอยู่ก่อนตารางจริง ดึงค่า "ชั้นปี" มาใส่เป็น
   "ห้อง" ให้อัตโนมัติ, ดึง "รหัสกลุ่มเรียน"/"ชื่อกลุ่มเรียน"/"ครูที่ปรึกษา" มาเก็บเป็นข้อมูล
   กลุ่มเรียนแยกไว้, ดึง "ประเภทผู้เรียน"/"สถานะ" มาเก็บต่อคน และข้ามนักเรียนที่สถานะ
   พ้นสภาพ/ลาออก/ตัดออกให้อัตโนมัติด้วย)
2. กรอกรายชื่อในเทมเพลต (ถ้าใช้เทมเพลตของระบบ) หรือเตรียมไฟล์รายงานจากระบบทะเบียนให้พร้อม
3. กด "นำเข้ารายชื่อจากไฟล์ (Excel/CSV)" เลือกไฟล์ ระบบจะสร้างข้อมูลนักเรียนทั้งหมดทันที
   (ข้ามรหัสที่มีอยู่แล้วในระบบอัตโนมัติ ไม่ทับข้อมูลเดิม รองรับหลายชีท/หลายห้องในไฟล์เดียว)
4. ใช้ dropdown "กลุ่มเรียน/ห้อง:" ด้านบนตาราง เพื่อกรองดูเฉพาะห้องที่ต้องการ — ระบบจะแสดง
   รหัสกลุ่มเรียน/ชื่อกลุ่มเรียน/ครูที่ปรึกษาของห้องนั้นให้ดูด้วย (ถ้ามีข้อมูลจากไฟล์ที่นำเข้า)
5. ต่อไปดับเบิลคลิกที่แถวของนักเรียนแต่ละคนในตาราง เพื่อเลือกมาถ่ายภาพใบหน้า (ไปขั้นตอน B ข้อ 2-3)

**วิธี B - กรอกทีละคนผ่านฟอร์ม:**
1. กรอกรหัสนักเรียน, ชื่อ-สกุล, ห้อง แล้วกด "บันทึกข้อมูลนักเรียน"
2. กด "เปิดกล้อง"
3. ให้นักเรียนหันหน้าเข้ากล้อง (ตรง/เอียงซ้าย/เอียงขวา/มีแว่น-ไม่มีแว่น) กด "ถ่ายภาพ + เก็บใบหน้า"
   ทำซ้ำ 3-5 ครั้งต่อคน ยิ่งหลายมุมยิ่งจดจำแม่นขึ้น
4. ทำซ้ำสำหรับนักเรียนคนถัดไป (ประมวลผลได้ทีละคน แนะนำทำช่วงเปิดเทอมหรือคาบโฮมรูม)

### ขั้นตอนที่ 2: สร้างกิจกรรม (Tab "จัดการกิจกรรม")
กรอกชื่อกิจกรรม วันที่ สถานที่ แล้วกด "สร้างกิจกรรม"

### ขั้นตอนที่ 3: เช็คชื่อ (Tab "เช็คชื่อ")
1. เลือกกิจกรรมจากรายการ
2. กด "เริ่มเช็คชื่อ (เปิดกล้อง)"
3. ตั้งกล้องไว้ที่ทางเข้างาน ให้นักเรียนเดินผ่านหน้ากล้องทีละคน/กลุ่มเล็ก
   ระบบจะตรวจจับใบหน้า จับคู่กับฐานข้อมูล และบันทึกเวลาเช็คชื่ออัตโนมัติ
   (กันเช็คซ้ำถี่ๆ ด้วยคูลดาวน์ 5 วินาทีต่อคน ปรับได้ใน config.py)

### ขั้นตอนที่ 4: ดูรายงาน (Tab "รายงาน")
เลือกกิจกรรม ดูรายชื่อ "เข้าร่วม" และ "ขาด" กด "ส่งออก Excel" เพื่อบันทึกไฟล์ .xlsx
(ไฟล์จะถูกบันทึกในโฟลเดอร์ `data/exports/`)

## การปรับแต่งสำหรับ 2,000 คน

- **CPU ขึ้น 90-100% ตลอดเวลา**: มี 2 สาเหตุที่แก้ไว้แล้วในระบบนี้:
  1. `onnxruntime` (ตัวรันโมเดล AI) ค่าเริ่มต้นใช้ทุก physical core และ "spin-wait" ตลอดเวลา
     แก้ด้วยการจำกัด thread + ปิด spin ใน `config.py`:
     ```python
     ONNX_INTRA_OP_THREADS = 2
     ONNX_INTER_OP_THREADS = 1
     ONNX_DISABLE_SPINNING = True
     ```
  2. InsightFace ค่าเริ่มต้นโหลด **5 โมเดล** (detection, recognition, landmark 3D, landmark 2D, gender/age)
     แต่ระบบนี้ใช้จริงแค่ detection + recognition จึงตัดอีก 3 ตัวทิ้งด้วย `allowed_modules` ใน
     `face_engine.py` ช่วยลดภาระ CPU ลงได้มาก (มีรายงานยืนยันว่าเร็วขึ้น ~30% หรือมากกว่านั้น)

  ถ้าเครื่องมีหลาย core มากๆ (8+) ลองปรับ `ONNX_INTRA_OP_THREADS` เป็น 3-4 เพื่อความเร็วเพิ่มขึ้น
  โดยที่ CPU ยังไม่ขึ้นเต็ม 100% ตลอด — ต้องลองปรับดูให้เหมาะกับเครื่องจริง (trade-off ความเร็ว vs CPU)

- **ความแม่นยำ**: ปรับ `RECOGNITION_THRESHOLD` ใน `config.py` (ค่าเริ่มต้น 0.45)
  - ค่าสูงขึ้น → เข้มงวดขึ้น เช็คชื่อผิดคนน้อยลง แต่บางครั้งจำหน้าตัวเองไม่ได้ (ต้องขยับ/ลองใหม่)
  - ค่าต่ำลง → จำง่ายขึ้น แต่เสี่ยงจับคู่ผิดคนมากขึ้น
  - แนะนำทดสอบกับกลุ่มตัวอย่าง 50-100 คนก่อนใช้จริงทั้งโรงเรียน แล้วค่อยปรับ

- **ความเร็ว**: ถ้าเครื่องมี GPU (NVIDIA) และติดตั้ง `onnxruntime-gpu` แทน `onnxruntime` ธรรมดา
  พร้อมตั้งค่า `CTX_ID = 0` ใน `config.py` จะเร็วขึ้นมาก เหมาะกับตอนมีคนเข้าแถวจำนวนมากพร้อมกัน

- **หลายจุดสแกน**: ถ้าต้องการหลายจุดพร้อมกัน (ลดคิว) ให้รันโปรแกรมนี้แยกเครื่องหลายเครื่อง
  โดยให้ไฟล์ `data/attendance.db` อยู่บน Shared Folder เดียวกัน (Windows File Sharing)
  หรือแจ้งอาจารย์ได้หากต้องการอัปเกรดเป็นสถาปัตยกรรม Client-Server (FastAPI + PostgreSQL)
  รองรับหลายจุดสแกนพร้อมกันได้ดีกว่า SQLite ในระยะยาว

## ข้อควรระวังด้าน PDPA

ข้อมูลใบหน้าเป็นข้อมูลชีวมิติ (sensitive personal data) ตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
ก่อนใช้งานจริงควร:
- ขอความยินยอม (consent) จากนักเรียน/ผู้ปกครอง เป็นลายลักษณ์อักษร
- แจ้งวัตถุประสงค์การใช้ข้อมูลให้ชัดเจน (ใช้เช็คชื่อกิจกรรมเท่านั้น)
- จำกัดสิทธิ์เข้าถึงไฟล์ `data/attendance.db` เฉพาะเจ้าหน้าที่ที่เกี่ยวข้อง
- มีนโยบายลบข้อมูลเมื่อนักเรียนพ้นสภาพ หรือครบกำหนดเก็บ
